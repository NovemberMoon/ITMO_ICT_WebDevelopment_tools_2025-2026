## 1. Введение

Вторая часть лабораторной работы направлена на изучение эффективности подходов `threading`, `multiprocessing` и `asyncio` в задачах, связанных с вводом-выводом (I/O-bound). При выполнении сетевых HTTP-запросов и транзакций в базу данных процессор большую часть времени простаивает в ожидании ответа от удаленных узлов.

В рамках задания требовалось разработать программы для параллельного парсинга информации о книгах с нескольких веб-сайтов. Каждая программа должна содержать функцию `parse_and_save(url)`, которая загружает HTML-страницу, парсит ее, выводит результат на экран и сохраняет заголовок (а также сопутствующие метаданные) в базу данных из Лабораторной работы №1. Список URL-адресов должен быть предварительно разделен на равные части. Требуется произвести замеры времени выполнения и прокомментировать результаты сравнения.

### 2.1. Механизм парсинга и сохранения данных

Внутри каждой из трех программ общий пул из 100 ссылок динамически делится на 8 равных частей (чанков), которые затем распределяются между параллельными подзадачами.

Процесс сбора данных состоит из двух логических этапов.

На **первом этапе** происходит извлечение данных. Библиотека `BeautifulSoup` анализирует HTML-разметку страницы и собирает ключевую информацию о книге: название, автора, год издания, язык, аннотацию и список жанров. Для обеспечения совместимости со структурой базы данных генерируется уникальный код `bcid`.

```python
def extract_book_info(html: str, url: str) -> dict:
    """Функция извлечения и нормализации данных из HTML (модуль utils.py)"""
    soup = BeautifulSoup(html, 'html.parser')

    # ... логика парсинга в зависимости от структуры целевого сайта ...
    # Пример извлечения для Standard Ebooks:
    title_tag = soup.find('h1', attrs={'property': 'schema:name'})
    title = title_tag.get_text(strip=True) if title_tag else "Неизвестное название"

    return {

        "title": title[:100],
        "author": author[:100],

```

На **втором этапе** извлеченные данные передаются в функцию `parse_and_save(url)`. Алгоритм инициирует загрузку страницы, вызывает функцию парсинга и транслирует полученный словарь в ORM-модели `SQLModel` для сохранения в таблицы базы данных. Ниже представлен фрагмент синхронной функции, которая используется в многопоточном и многопроцессном подходах (включая механизм защиты от сетевых сбоев `Retry`):

```python
def parse_and_save(url: str):
    """Синхронная функция загрузки и сохранения данных"""
    for attempt in range(3):
        try:
            # 1. Загрузка HTML-страницы
            response = requests.get(url, headers=HEADERS, timeout=10)
            response.raise_for_status()

            # 2. Парсинг данных
            book_data = extract_book_info(response.text, url)
            if book_data["title"] == "Неизвестное название":
                return

            # 3. Сохранение в базу данных из Лабораторной №1
            save_to_db_sync(book_data)

            # 4. Вывод результата на экран
            print(f"[Thread-{threading.current_thread().name}] Сохранено: '{book_data['title']}'")
            return
        except RequestException:
            time.sleep(1) # Механизм повтора при сетевых сбоях
        except Exception as e:
            print(f"[Thread-{threading.current_thread().name}] Ошибка: {e}")
            return
```

```python
# Особенность асинхронного подхода: неблокирующее ожидание сети и БД
async def parse_and_save(url: str, session: aiohttp.ClientSession):
    for _ in range(3):
        try:
            # Управление возвращается в Event Loop во время ожидания сети
            async with session.get(url, timeout=10) as response:
                response.raise_for_status()
                html = await response.text()

                book_data = extract_book_info(html, url)
                if book_data["title"] == "Неизвестное название":
                    return

                # Асинхронная транзакция в базу данных
                await save_to_db_async(book_data)

                print(f"[Async] Сохранено: '{book_data['title']}'")
                return
        except (aiohttp.ClientError, asyncio.TimeoutError):
            await asyncio.sleep(1)
        except Exception as e:
            print(f"[Async] Ошибка: {e}")
            return
```

### 2.2. Особенности конкурентных подходов

Главное архитектурное различие подходов заключается не столько в функциях-обработчиках, сколько в механизмах **оркестрации** – как именно инициализируются воркеры и как между ними распределяются задачи (чанки URL-адресов).

Каждая программа реализует уникальную архитектурную модель распределения сетевой нагрузки:

1. **Многопоточность (`task2_threading.py`):**

    Разделенные на равные части списки ссылок передаются 8 системным потокам. Главной особенностью потоков в сетевых (I/O) задачах является то, что при выполнении блокирующего HTTP-запроса поток временно освобождает GIL. Это позволяет планировщику ОС запустить другой поток и отправить следующий запрос, реализуя конкурентное выполнение в рамках одного процесса.

    ```python
    def run_threading():
        """Оркестрация многопоточного выполнения."""
        urls = load_urls()
        chunks = divide_into_chunks(urls, num_threads=8)
        threads = []

        # Создание и запуск легковесных потоков ОС
        for i, chunk in enumerate(chunks):
            t = threading.Thread(target=thread_worker, args=(chunk,), name=str(i+1))
            threads.append(t)
            t.start()

        # Блокировка главного потока до завершения всех дочерних
        for t in threads:
            t.join()
    ```

2. **Многопроцессность (`task2_multiprocessing.py`):**

    Используется пул изолированных процессов. Особенность архитектуры Shared-Nothing (отсутствие общей памяти) приводит к тому, что каждый из 8 процессов вынужден самостоятельно с нуля инициализировать TCP-соединения с веб-серверами и устанавливать новые подключения к СУБД, что создает значительные накладные расходы.

    ```python
    def run_multiprocessing():
        """Оркестрация многопроцессного выполнения."""
        urls = load_urls()
        chunks = divide_into_chunks(urls, num_processes=8)
        processes = []

        # Создание "тяжелых", полностью изолированных процессов ОС
        for i, chunk in enumerate(chunks):
            p = multiprocessing.Process(target=process_worker, args=(chunk,), name=str(i+1))
            processes.append(p)
            p.start()

        for p in processes:
            p.join()
    ```

3. **Асинхронность (`task2_async.py`):**

    Используются ключевые слова `async/await`, неблокирующая библиотека `aiohttp` и асинхронный драйвер для БД `asyncpg`. Все URL обрабатываются в рамках **одного системного потока** (Event Loop). Для оптимальной работы создается единая сессия, переиспользующая базовое TCP-соединение (Keep-Alive) для всех запросов.

    ```python
    async def run_async_logic():
        """Оркестрация асинхронного выполнения (внутри Event Loop)."""
        urls = load_urls()
        chunks = divide_into_chunks(urls, num_tasks=8)

        # Единая сессия TCP-соединений (существенное ускорение сетевого взаимодействия)
        connector = aiohttp.TCPConnector(limit=30)
        async with aiohttp.ClientSession(headers=HEADERS, connector=connector) as session:

            # Задачи не создают новых потоков ОС, а просто передаются планировщику
            workers = [asyncio.create_task(async_worker(chunk, session)) for chunk in chunks]

            # Конкурентное ожидание завершения всех корутин
            await asyncio.gather(*workers)
    ```

## 4. Анализ результатов и сравнение подходов

Данные, представленные в Таблице 1, наглядно демонстрируют, что в задачах ввода-вывода эффективность парадигм программирования кардинально отличается от вычислительных задач:

1. **Максимальная эффективность Asyncio:**

    Асинхронная программа стабильно показывает лучшее среднее время (~14.6 сек). Благодаря неблокирующим сокетам один системный поток способен удерживать десятки одновременных сетевых подключений. Отсутствие системных затрат на создание потоков или процессов делает этот подход максимально быстрым и легковесным по потреблению оперативной памяти.

2. **Приемлемая, но нестабильная работа Threading:**

    Потоки успешно справляются с обходом GIL при I/O-операциях (показывая среднее время ~38.1 сек). Однако прямая зависимость от планировщика ОС делает этот подход уязвимым к сетевым задержкам. В «Тесте 3» (66.6 сек) видно, как отсутствие ответа от удаленного сайта привело к длительной блокировке потока, что существенно исказило общее время выполнения программы.

3. **Низкая эффективность Multiprocessing:**

    Многопроцессность, показавшая лучшие результаты в математических вычислениях, в сетевой задаче оказалась самым медленным решением (~44.8 сек). Наличие выделенных ядер процессора не ускоряет загрузку HTML-кода по сети. Ресурсы операционной системы расходуются нецелесообразно на инициализацию процессов и дублирующихся сетевых соединений.

## 5. Заключение

Выполненное профилирование подтверждает, что для разработки сетевых приложений, параллельных веб-парсеров и сервисов с интенсивной нагрузкой на базу данных (I/O-bound) наиболее производительным паттерном является асинхронное программирование (`asyncio`). Использование многопроцессности (`multiprocessing`) в таких случаях уступает по скорости и ведет к нецелевому расходу системных ресурсов.
